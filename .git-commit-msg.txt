refactor: call it the app, not the "shell"

The APK is the app 南瓜坞; "shell" was leftover scaffolding vocabulary from when
this was described as a shell wrapped around the Pumpkin server. It leaked into
everything a user reads - "壳有新版本", "壳已是最新", the About row - which reads
as jargon to anyone who did not write it.

User-visible strings now say 南瓜坞. Identifiers follow: ShellAsset ->
AppAsset, checkShellUpdate -> checkAppUpdate, shellVersion -> appVersion,
SHELL_UPDATE -> APP_UPDATE, and so on.

Chinese prose was rewritten per phrase rather than by find-and-replace, because
a blind 壳 -> 南瓜坞 swap turns "轻壳主界面" into "轻南瓜坞主界面".

Two names are deliberately untouched because other things already depend on
them:

  Prefs.NAME = "pumpkin_shell" is the SharedPreferences filename; renaming it
  silently discards every stored setting on upgrade.

  The Release asset pumpkin-shell.apk is a documented permanent download URL
  (releases/latest/download/pumpkin-shell.apk), so it keeps its name. Nothing
  in the code depends on it either way - fetchAppAsset matches on the .apk
  extension, not the filename.

docs/shell-self-update.md was safe to move, so it is now docs/app-self-update.md.
